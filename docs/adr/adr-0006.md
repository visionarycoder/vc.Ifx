# ADR-0006: Standardize ADR structure and navigation

## Status

Accepted

## Date

2026-09-09

## Context

The repository needs a clear and consistent way to record architectural decisions as they evolve. Without a standard set of navigation files, ADRs become harder to discover, harder to maintain, and easier to lose in a broad documentation tree.

The ADR inventory should balance historical continuity with practical maintainability. Contributors need a low-friction process for adding new decisions while preserving a clear record of the current direction.

## Decision

We will standardize ADR documentation in `docs/adr` with the following structure:

- a reusable [ADR template](./adr-template.md)
- a [README](./README.md) describing purpose and ADR lifecycle
- a [table of contents](./toc.md) listing all decisions
- an [index](./index.md) providing a searchable catalog of accepted, superseded, and deprecated records
- a naming pattern of `adr-XXXX.md` for each decision record

This structure is designed to keep the decision trail discoverable while staying easy to update when new architectural choices are made.

## Consequences

### Positive

- ADRs are easier to discover and navigate.
- Contributors can add new records without inventing a new format.
- The historical record remains intact while the current guidance stays easy to find.
- Documentation links become more stable and easier to maintain.

### Negative

- Maintaining the ADR catalog requires ongoing curation as new decisions are added.
- Some older ADRs may need periodic cleanup or a clear supersession note.

## Alternatives considered

- Keep ADRs as a loose collection of markdown files without navigation support.
  - Rejected because discoverability is poor and the decision trail becomes harder to maintain.
- Store ADRs at the repository root or in a single mixed docs folder.
  - Rejected because it weakens separation of concerns and makes navigation harder.
- Use only a template and index without a README or TOC.
  - Rejected because the folder is less approachable for new contributors and less consistent as the ADR set grows.
