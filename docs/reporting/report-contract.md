# Reporting Contract v1

Owner: Reporting worker; Updated: 2026-09-09; Status: implementation in flight.

## Boundary

`vc.Ifx.Roslyn.Reporting` is a net10.0 NuGet library. It accepts facts in memory
and returns versioned JSON and Markdown; it performs no report/source file or network I/O.
Roslyn reads installed framework metadata to resolve GeneratedCode attributes,
including aliases, without mistaking same-named handwritten attributes for generated code.
The script host owns reading build artifacts and writing `report.json` and
`report.md`. Analyzers remain deterministic diagnostic producers and never write
reports. No reference to the aggregator or analyzer implementation is introduced.

## Inputs and Provenance

One request identifies the revision and expected package inventory explicitly.
Each package supplies its compiler SARIF 2.1.0 and evaluated handwritten Compile
sources (repository-relative paths, text, and compilation preprocessor symbols).
The request supplies the raw merged Coverlet JSON used by the exact coverage gate,
not a rounded percentage or a previously summarized report. The host accepts an
explicit current-run coverage directory, never the newest arbitrary historical
file. Full mode requires the runner's unfiltered full-run context and all packages.
Input SHA-256 fingerprints, revision and metric policy version are retained;
wall-clock timestamps and machine-specific absolute paths are not report fields.

Missing SARIF, missing source inventory, missing coverage modules, empty executable
coverage, invalid source syntax, malformed input, and unsupported schema versions
cannot pass. Missing measurements are JSON null and Markdown `Unknown`, accompanied
by an issue. Malformed artifacts throw; incomplete but readable evidence produces
an unsuccessful report for diagnosis. Extra coverage modules do not substitute for
expected ones. Duplicate expected packages, evidence or coverage modules are errors.

## Metrics and Analyzer Coordination

Coordination request for Nash (01a089a4-9b1d-7c01-b186-8b108591f32b): retain the
existing IFX1100 SARIF properties `MetricName=ControlFlowNestingDepth`,
`MetricVersion=ifx-control-nesting-v1`, `MeasuredValue`, and `Threshold`.
Direct task messaging is unavailable to this worker; Orchestrator must relay this
request and confirm compatibility. The reporting package does not infer complete
metrics from threshold-only diagnostic emissions or require an analyzer change.

The reporter independently analyzes actual Roslyn syntax under the versioned
`ifx-method-source-v1` policy. Scope is ordinary method declarations, including
expression bodies. Constructors, operators, accessors and anonymous/local functions
are not claimed as measured methods in v1. Nested functions do not contribute to
their enclosing method's decision or nesting counts. Abstract/extern declarations
have unknown cyclomatic, nesting and method-length values (parameter count is known).

- Cyclomatic complexity: one plus each if, for, foreach, while, do, catch,
  non-default switch label/arm, conditional expression, `&&`, `||`, and `??`.
  This syntax policy is not advertised as Microsoft's CA1502 or a CFG metric.
- Nesting: maximum nested if, switch, for, foreach, while, do and try statements,
  excluding nested functions; body starts at zero. This matches IFX1100's
  `ifx-control-nesting-v1`, not the legacy CQ block-depth helper.
- Method length: inclusive physical line span of the body/expression, including
  comments and blank lines in that span; not statement count or logical LOC.
- Parameter count: declared parameter-list entries, including extension receivers.
- Policy classification: nesting >4 is `Review`; the other three measurements
  have no invented thresholds. Unknown bodies are `Unknown`, not zero.

Generated complexity exclusions: files under obj/bin, standard .g.cs,
.generated.cs and .designer.cs suffixes, and a leading `// <auto-generated` marker
(after whitespace). The host's
evaluated Compile inventory excludes test projects. Exclusions are listed in the
report, not silently discarded. Member-level GeneratedCode attributes must be
reported explicitly as excluded; CompilerGenerated never excludes handwritten
records or async methods. Coverage uses the existing pipeline exclusions unchanged
(GeneratedCodeAttribute and obj-generated sources), with no additional report-side
coverage exclusions.

## Outputs and Gates

Schema version 1: revision, metricPolicy, passed, issues, package rows. Each row
contains diagnostics, source fingerprints/exclusions, ordinary-method metrics and
exact line/branch covered/total counts. Arrays use ordinal package/path/rule/span
ordering. JSON uses camelCase and explicit nulls; Markdown uses LF, invariant
numbers and escaped table text. The same inputs produce byte-identical outputs.
Diagnostics preserve severity, rule ID, message and metric properties; suppressed
diagnostics remain visible but are not treated as active errors. Missing severity
is `unknown`, never silently green. Warnings/review metrics remain visible; active
errors and incomplete evidence fail. Coverage passes only when covered equals total
for both measures and line total >0; branchless 0/0 has unknown percentage, not 100%.

CI captures project-specific SARIF and Compile manifests during the same clean
build, then tests/coverage, then reporting, then pack. Reports are retained with
TestResults even on gate failure. Local scoped reports must be labeled scoped and
cannot serve as full integration evidence. No publishing or hosted settings changes.
